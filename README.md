# dsh-persona-hub

给 **DeepSeek Harness (DSH)** 用的人格中枢插件：把一个角色绑到聊天会话上，给她分层长期记忆、心情，
以及一块自带的面板（改人格、改记忆、看进度）。

> 本仓库是**框架**，不含任何预置的人格 / 作息 / 情绪词表 —— 装完由你自己填（见 §6）。

## 1. 它是什么 / 不是什么

**是**：一个**记忆与人格层**。它做三件事——

- 把某个人格（一段"你是谁、你怎么说话"的正文）注入到指定会话的系统提示里；
- 维护**四层记忆**（随身 → 性格 → 候选 → 经历），并自动把经历浓缩上挑；
- 提供一个面板，让你改人格、改记忆、看自动总结进度。

**不是**：它**不连 QQ、不连微信、不发消息**。它不关心消息从哪来 —— 那是"渠道插件"的活。
它只需要知道一件事：**这段会话属于哪个聊天**。

## 2. 需要哪些软件（整条链路）

```
        QQ 号（建议用小号）
             │
        ┌────▼─────┐
        │  NapCat  │   把 QQ 变成 OneBot v11 服务端（开一个 WebSocket 端口）
        └────┬─────┘
             │  ws://127.0.0.1:3001 （带 accessToken）
        ┌────▼──────────┐
        │  渠道插件      │   例：dsh-onebot-qq —— 收发消息、建会话、把回复发回 QQ
        └────┬──────────┘
             │  DSH 会话（id 形如 onebot-private-<qq>）
        ┌────▼──────────┐
        │ DSH 本体       │   宿主：跑插件、管 agent、调模型
        └────┬──────────┘
             │  会话 + 系统提示
        ┌────▼────────────┐
        │ dsh-persona-hub │   ← 本插件：注入人格 + 记忆（不碰网络）
        └────┬────────────┘
             │  provider / apiKey
        ┌────▼─────┐
        │ 模型通道  │   例：DeepSeek / MiniMax / 其他 OpenAI 兼容端点
        └──────────┘
```

| 组件 | 必需吗 | 说明 |
|---|---|---|
| **DSH 本体** | **必需** | 宿主。跑起来后 Web 界面在 `http://127.0.0.1:19387` |
| **模型通道** | **必需** | 至少一个可用的 provider + apiKey，否则一个字都说不出来 |
| **dsh-persona-hub** | **必需** | 本插件 |
| **渠道插件** | 要接聊天软件才需要 | 例：`dsh-onebot-qq`。负责把消息变成 DSH 会话、把回复发回去 |
| **NapCat**（或同类） | 要接 **QQ** 才需要 | OneBot v11 实现：把 QQ 协议包成 WebSocket。同类还有 LLOneBot、Lagrange 等 |
| **一个 QQ 号** | 要接 QQ 才需要 | **建议用小号**，别拿主号挂第三方协议端 |
| Node.js | 通常不必单独装 | DSH 自带运行时；只在你想跑本仓库的脚本时需要 ≥22 |

## 3. 要不要用 NapCat？

**看你想让角色在哪里说话**：

| 你的场景 | 需要 NapCat 吗 | 需要渠道插件吗 |
|---|---|---|
| 只想在 DSH 里试 persona-hub（本机对话） | **不需要** | 不需要（把 `scope` 留空即可，见 §4-Step3 备注） |
| 让角色在 **QQ** 上说话 | **需要** | 需要（如 `dsh-onebot-qq`） |
| 让角色在别的平台说话（Telegram / Discord / 自研） | 不需要，换对应渠道 | 需要 |

**本插件与 NapCat 没有任何直接关系**。它只认一条约定（§3.1），所以换个渠道、换个平台都能用。

### 3.1 唯一的硬约定：会话 id

```
私聊：onebot-private-<对方QQ>       例：onebot-private-100000001
群聊：onebot-group-<群号>           例：onebot-group-123456789
```

- 前缀（`onebot-`）与中间那段（`private` / `group`）就是 persona-hub 判断"这是不是一个聊天会话"的依据；
- 换成别的渠道插件，只要 id 长这样，本插件照样工作；
- 每个 id = 一段独立会话 = 一套独立的"经历"记忆，但它们共享同一份"随身 / 性格"。

## 4. 从零到能聊：五步

### Step 0 · 让 DSH 先跑起来

```bash
dsh web          # 或直接启动 DSH 桌面端
```

✅ **成功的样子**：浏览器打开 `http://127.0.0.1:19387` 能看到聊天界面。

### Step 1 · 配一个模型通道

在 `~/.dsh/profiles/<profile>/cordis.patch.yml` 里配 provider 与 apiKey（写 env 变量名，值放环境变量），例如：

```yaml
- id: llm-pi-ai
  name: "@deepseek-ai/dsh-llm-pi-ai"
  config:
    providers:
      deepseek:
        baseURL: https://api.deepseek.com/v1
        apiKeyEnv: DEEPSEEK_API_KEY
        models:
          - id: deepseek-chat
```

✅ **成功的样子**：DSH 里随便发一句，模型能回话。

### Step 2 · 装渠道 + NapCat（只为接 QQ）

**2a. NapCat 侧**
1. 装 NapCat（桌面版或注入版），登录你的**小号 QQ**；
2. 打开它的 **WebSocket 服务端**功能，记下 **端口**（例：`3001`）和 **accessToken**（自己设一串）。

**2b. 渠道插件侧**（以 `dsh-onebot-qq` 为例，装法以该插件说明为准）

```yaml
- id: dsh-onebot
  name: dsh-onebot-qq
  config:
    mode: forward                             # 正向：我们主动连 NapCat
    accessToken: <与 NapCat 里一致>
    botQQ: "100000000"                        # 机器人自己的 QQ 号
    dmPolicy: allowlist                       # 私聊策略
    allowFrom: ["100000001"]                  # 允许私聊的人
    adminUsers: ["100000001"]                 # 管理员（可用 / 命令）
    requireMention: true                      # 群里要 @ 才理
    workspacePath: <渠道插件的工作目录>         # 聊天数据落盘处
```

> ws 地址一般是 `ws://127.0.0.1:3001`，端口与 2a 保持一致。

**重启 DSH**，然后用大人号给机器人小号发一句私聊。

✅ **成功的样子**：DSH 里出现一个会话（例如 `onebot-private-100000001`），机器人也回了一句话。

### Step 3 · 装 dsh-persona-hub（本插件）

```bash
# 3a. 放进 profile（link 方式：改源码立刻生效）
#     编辑 ~/.dsh/profiles/<profile>/package.json，在 dependencies 里加：
#     "dsh-persona-hub": "link:<本仓库的绝对路径>"
cd ~/.dsh/profiles/<profile>
pnpm install          # 或 npm install

# 3b. 注册到 profile：编辑 ~/.dsh/profiles/<profile>/cordis.patch.yml
#     - id: persona-hub
#       name: dsh-persona-hub
#       config:
#         scope: qq        # 只在 QQ 渠道会话注入；留空 = 所有会话都注入
```

**重启 DSH**，打开 `http://127.0.0.1:19387/persona-hub`。

✅ **成功的样子**：出现「人格中枢」面板，有人格库 / 她的记忆 / 自动总结进度 / 机器人账号 等卡片。

> **想先不接 QQ 试试？** 把 `scope` 留空（或删掉这一项），插件对所有会话生效；
> 在面板里建一个人格并设为默认，然后在 DSH 里正常聊天，就能看到她带着人格说话。

### Step 4 · 第一次配置（在面板里点）

| 顺序 | 在哪 | 填什么 | ✅ 成功的样子 |
|---|---|---|---|
| 1 | 「机器人账号」卡片 | 机器人 QQ 号 → 绑到某个人格 | 卡片显示"当前：<人格名>" |
| 2 | 「人格库」卡片 | 新建人格，写**正文**（她是谁、怎么说话、在意什么） | 不再标「正文为空（不会生效）」 |
| 3 | 插件配置 / 面板偏好 | **`ownerQq`**（谁是"主人"，可写多个） | 私聊时身份那段显示"他是配置里指定的主人" |
| 4 | 「素材目录」 | （可选）她能用的图片目录 | 留空 = `memories/<人格id>/stickers` |
| 5 | 「她的一天」 | （可选）作息：`[{"at":"09:00","where":"地点","doing":"做什么"}]` | 留空 = 不作息、不编造 |

> `ownerQq` 两个地方都能写，**面板偏好优先**：
>
> ```yaml
> - id: persona-hub
>   name: dsh-persona-hub
>   config:
>     scope: qq
>     ownerQq: ["100000001"]     # 主人 QQ（可多个）
> ```

### Step 5 · 验收清单

| 你要看到的 | 说明 |
|---|---|
| 大人号私聊，她**带人格**回话 | 人格绑定生效 |
| 陌生号私聊，她**明显收敛**（不给私事） | 身份判定生效 |
| 面板「她的记忆」里**经历**在增长 | 经历层在记 |
| 面板「自动总结进度」显示条数 / 是否该催 | 自动总结在跑 |
| 面板「QQ 接入体检」没有红色告警 | 渠道链路健康 |

## 5. 配置总表

### 5.1 本插件（`cordis.patch.yml` 里该行的 `config:`）

| 键 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `scope` | string | 空 | 注入范围。`qq` = 只在 QQ 渠道会话生效；留空 = 所有会话 |
| `ownerQq` | string[] | `[]` | "主人"的 QQ 号。留空 = 分不出主人，所有会话都按"非主人"处理 |

面板里可改的偏好（存在数据目录，**优先于**配置）：自动总结的条数与闲置小时、心情开关、
作息表、素材目录、默认人格、会话例外等。

### 5.2 渠道插件（以 `dsh-onebot-qq` 为例）

| 键 | 含义 |
|---|---|
| `mode` | `forward` = 我们主动连 NapCat 的 ws 端口 |
| `accessToken` | 必须与 NapCat 里设置的一致 |
| `botQQ` | 机器人自己的 QQ 号 |
| `dmPolicy` / `allowFrom` | 私聊策略与白名单 |
| `requireMention` | 群里是否需要 @ 才回 |
| `adminUsers` | 管理员，可用 `/` 命令 |
| `workspacePath` | 聊天数据落盘目录 |
| `splitByLine` / `splitTypingMsPerChar` / `splitLineGapMs` | 出站拆行与打字节奏 |

### 5.3 NapCat 侧

| 项 | 值 |
|---|---|
| 服务 | 打开「WebSocket 服务端」 |
| 端口 | 例 `3001`（与渠道插件一致） |
| accessToken | 自定义一串；与渠道插件一致 |
| 登录的 QQ | 机器人小号 |

## 6. 面板怎么用

打开 `http://127.0.0.1:19387/persona-hub`（也可在 DSH 界面点「人格中枢」→「在新标签页打开完整界面」）。

| 卡片 | 干什么 |
|---|---|
| **人格中枢** | 总览：人格数、当前绑定 |
| **人格库** | 新建 / 编辑人格：名字、emoji、标签、**正文**、启用开关 |
| **机器人账号** | 把机器人 QQ 号绑到人格（主绑定：这个号收到的所有会话默认用它） |
| **会话例外（高级）** | 给某个群 / 某个人单独安排人格，**优先于**账号绑定 |
| **她的记忆** | 四层记忆一览与编辑：随身 / 性格 / 候选 / 经历 / 总结 |
| **记忆管理** | 逐行编辑某一层，或把候选晋升到随身 |
| **自动总结进度** | 每个聊天攒了多少条、是否该催；可改阈值，也可「现在立刻催她收一次」 |
| **她的一天** | 作息表（留空 = 不启用） |
| **素材目录** | 她能用的图片素材目录 |
| **她能做的事** | 面板上开关她的动作能力 |
| **模型** | 给这个机器人单独选模型 |
| **QQ 接入体检** | 检查渠道配置（botQQ、白名单、token 等）是否自洽 |

## 7. 数据放哪 / 隐私

```
~/.dsh/dsh-persona-hub/
  personas.json            人格正文、账号绑定、偏好（含每聊天的总结进度）
  memories/<人格id>/
    随身.txt 性格.txt 候选.txt 总结.txt
    _流水-<会话>.txt        每个聊天的原始经历
    作息.json              可选，覆盖默认作息
    history/<日期>/        每 24 小时固化一份（同一天只写一次）
    stickers/              她的图片素材
```

- **全部数据都在你本机**，本插件不上传任何东西；
- 仓库里的 `.gitignore` 已忽略 `personas.json`、`memories/`、`backups/`、`*.bak-*`、`.env` 等
  —— 即使你把仓库克隆到本机当工作目录用，这些私人数据也不会被 git 跟踪；
- 本仓库**不含任何预置的人格 / 作息 / 情绪词表**，也不含作者的任何个人数据。

## 8. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 打开 `/persona-hub` 是 404 | 插件没挂上：检查 `package.json` 的 link 与 `cordis.patch.yml` 的注册行，然后**重启 DSH** |
| 她完全不回话 | 先看渠道：NapCat 的 ws 端口 / token 与渠道插件是否一致；再看模型通道是否可用 |
| 她回话但没人格 | ①`scope` 是否限制了范围；②该会话是否绑了人格（「机器人账号」/「会话例外」）；③人格**正文是否为空** |
| 把陌生人也当成熟人 | 没配 `ownerQq`。补上后重启 |
| 记忆不增长 | 「自动总结进度」里看条数与阈值；经历是**逐条**累积的，阈值到了才催 |
| 群里她不说话 | `requireMention` 默认开：需要 @ 她或回复她 |
| 感觉她"编造"自己的行程 | 作息表为空 → 插件**不给任何时间事实**（宁可不说，不编造）。要她"有生活"就填「她的一天」 |

## 9. 换渠道：任何渠道怎么接

这个插件**不绑 QQ**。它只管「谁在演哪个人格、记得什么、怎么说话」；
收发消息永远由渠道插件负责。所以换平台不用改这个插件 —— 只要渠道满足三条契约：

| 契约 | 渠道要做的事 | 一句话 |
|---|---|---|
| ① 会话命名 | 每个聊天一个**持久**会话，id 写成 `<渠道>-private-<号>`（单聊）或 `<渠道>-group-<号>`（群聊） | `<渠道>` 随便叫；**同一个聊天永远同一个 id**，重启也不许新建 |
| ② 入站 | 把用户消息投给上面那个会话 | 人格、四层记忆、情绪、作息、身份档位由本插件自动注入，渠道不用管 |
| ③ 出站说话 | 发之前问一句（见下），按返回的"条数 + 每条等多久"发 | 接上就继承"她的说话样子"；接不上她照旧会发，只是可能带旁白、一口气多条 |

最小接线（约 5 行，放在渠道插件的发送路径上）：

```js
const hub = this.ctx?.personaHub;                 // 同进程的插件服务
let plan = null;
if (typeof hub?.planSpeech === 'function') {
  try {
    const got = await hub.planSpeech({ text: plainText });   // ⚠ 必须 await（它是 async）
    if (got?.bubbles?.length > 0) plan = got;
  } catch { /* 忽略：下面走回退 */ }
}
if (plan !== null) {
  for (const b of plan.bubbles) {
    await sleep(b.delayMs);                       // 每条之前等这么久（她在"打字"）
    await send(chatId, b.text);
  }
} else {
  await send(chatId, plainText);                  // 取不到就照旧发（绝不能让消息卡住）
}
```

返回值形如：

```js
{ plain: '去掉旁白后的整段',
  bubbles: [ { text: '第一条', delayMs: 2510 }, { text: '第二条', delayMs: 2750 } ],
  dropped: 0 }
```

**现象对照**（接完渠道后照这个看）：

| 现象 | 说明 |
|---|---|
| 她带 `（笑）`这类旁白、一口气发八条 | 契约③没接（或忘了 await）—— 走的是渠道自己的老逻辑 |
| 她完全不说话 | 契约①或②没对上：会话 id 格式不对，或消息没投进那个会话 |
| 她"重新自我介绍" | 会话 id 变了（新建了会话）→ 她会当陌生人重新开始 |
| 想改说话方式 | 改本插件的偏好（最多几条 / 打字速度 / 间隔），不必动渠道插件 |

完整契约（反例、fail-open、工具清单 `handsText`、各渠道现状、边界）见同仓库的 **`CHANNEL.md`**。
